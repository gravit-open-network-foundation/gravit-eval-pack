# Independent reproducibility of verifiable decisions

**Technical note · Gravit Open Network Foundation · October 2026**

## Abstract

Third-party evaluation is only as strong as a third party's ability to check a result without
trusting whoever produced it. This note describes the Gravit verification stack — two IETF
Internet-Drafts (VEDS-00, GEVP-08), a reference verifier (Python, with a Rust port) and a
consensus engine — and an evaluation pack that lets anyone reproduce every published result with
one command. All numbers below are generated by that pack; none were written by hand.

## 1. The problem: report-centric versus evidence-centric assurance

In report-centric assurance, an evaluation produces a document and readers trust its author. In
evidence-centric assurance, a claim is accepted only with evidence that an independent party can
re-check mechanically, and the decision itself is a reproducible artefact. Dario Amodei
(*We Must Pace the Frontier*, September 2026) argues that "it seems vital to have a neutral third
party who can actually see the details" and that "the public deserves to know what is going on".
The Gravit stack addresses a narrower, mechanical part of that need: making the *decision* that
evidence justifies a claim checkable by anyone. It does not inspect model weights or internals.

## 2. Design

**Epistemic states.** A claim is classified as *Speculative Claim*, *Probabilistic Assessment* or
*Verified Fact*. Each normative rule (a *binding*) either licenses a state or can only demote one.

**Core invariant — no aggregation laundering.** Aggregating weak or non-independent evidence never
yields a Verified Fact. A Verified Fact requires COMMITTED convergence: at least two independently
produced records with honest-weight share h > 0.7 and adversarial share f < 0.3.

**Signed, independent evidence.** Each record carries an Ed25519 signature by a key listed in a
verifier registry. Keys of one operator count as one source. The registry itself is accepted only
if at least 3 of 5 root keys signed it. Unsigned, unknown, revoked, tampered or replayed records
are excluded, with the reason recorded.

**Freshness and provenance.** Under a declared freshness policy, stale, future-dated or malformed
timestamps demote the result; high-impact decisions additionally require an integrity hash.

**Reproducible decisions.** Every decision record is content-addressed: identical inputs give an
identical `decision_id` on any machine and in both implementations.

## 3. Results (from `make eval`)

- **Conformance:** 47 of 47 golden vectors of verifier v0.6.0 reproduced byte for byte.
- **Adversarial benchmark:** 32 cases in which a Verified Fact is claimed without justification —
  aggregation laundering, Sybil or non-independent sources, forged, tampered or replayed
  signatures, revoked keys, stale or malformed timestamps, missing provenance, missing trust root,
  and records whose signed verdict is "failed" or "no verdict".
  The verifier refused all 32, and granted the claim in every legitimate baseline and boundary case.
- **Correction (13 Oct 2026).** The earlier version of this note reported "27 of 27 refused" for
  verifier v0.5.0. That was true for the cases tested, but the cases did not cover the signed
  `result` field, and v0.5.0 ignored it: a record signed "check failed" still counted towards a
  Verified Fact. An external reviewer found this with a reproduction. Verifier v0.6.0 applies the
  signed result (`CANON-RES-012`); the five new attack cases are in the "Signed verdict" class.
- **Consensus under a 10x Sybil attack** (100 honest versus 1000 Sybil nodes, 30 rounds): the network
  confidence in the true claim reaches 0.9874, and the Sybil stake share falls below 0.001 % by round 9.
- **theta_critical calibration** (3000 claims): at theta = 0.73, TPR 91.7 %, FPR 7.3 %, ROC AUC 0.856.
  The rates are identical for every theta between 0.11 and 0.78. An earlier published trace reported
  TPR 93.4 % / FPR 0.4 % but had no generator and could not be reproduced; it is superseded (see draft-gravit-gevp-08),
  and kept unchanged for the record. The honest conclusion is that, after convergence, the threshold matters
  little; what decides the outcome is whether honest evidence outweighs the Sybils.

## 4. Applied to a live system

The same approach has been applied, read-only, to a production liquidity protocol on Solana:
every automated range-manager action and every swap re-checked against the protocol's declared
rules from the public ledger alone. The report will be published with the operator's consent.

## 5. Limits

- Registry and keys used here are test keys; the Foundation's root key ceremony is planned.
  No claim of production Sybil resistance is made until real, independently held keys exist.
- Under Gravit's own rules one checker is one opinion: a Verified Fact about any external system
  requires a second, independent operator to re-run and sign the same result.
- The verifier checks decisions about evidence. Producing good evidence — evaluations of a model,
  measurements of a system — remains the evaluator's work.

## 6. Reproduce

```bash
git clone https://github.com/gravit-open-network-foundation/gravit-eval-pack
cd gravit-eval-pack && make eval
```
